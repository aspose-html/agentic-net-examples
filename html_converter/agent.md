## Common Code Pattern

Below is a representative pattern that appears across the majority of examples.  
It demonstrates loading an HTML document, optionally binding data, converting it to an image, and logging the result.

```csharp
using System;
using System.IO;
using Aspose.Html;
using Aspose.Html.Converters;
using Aspose.Html.Saving;
using Aspose.Html.Rendering.Image;

class HtmlToImageExample
{
    static void Main()
    {
        // 1️⃣ Load the HTML source (file, URL or raw string)
        string htmlPath = @"C:\Samples\sample.html";
        var document = new HTMLDocument(htmlPath);

        // 2️⃣ (Optional) Bind dynamic data or set base URI
        // document.Window.SetProperty("myData", "value");
        // document.BaseUrl = new Uri("https://example.com/");

        // 3️⃣ Configure the output options (image format, DPI, page size, etc.)
        var saveOptions = new ImageSaveOptions(SaveFormat.Png)
        {
            // Example: high‑resolution PNG for printing
            ImageDevice = new ImageDevice
            {
                DpiX = 300,
                DpiY = 300,
                BackgroundColor = System.Drawing.Color.White
            },
            Page = new Page(0, 0, 1240, 1754) // A4 @300 dpi
        };

        // 4️⃣ Perform the conversion
        string outputPath = Path.Combine(
            Environment.CurrentDirectory,
            "output.png");

        Converter.ConvertHTML(document, saveOptions, outputPath);

        // 5️⃣ Log the outcome
        Console.WriteLine($"HTML converted to PNG successfully: {outputPath}");
    }
}
```

*Adjust the `SaveFormat`, `ImageDevice`, and `Page` settings to target JPEG, BMP, GIF, TIFF, PDF, DOCX, XPS, Markdown, MHTML, etc., as demonstrated in the individual files.*

## Category‑Specific Tips

### Key API Surface
- **Core conversion**: `Converter.ConvertHTML`, `Converter.RenderTo`
- **Document model**: `HTMLDocument`
- **Save options**: `ImageSaveOptions`, `PdfSaveOptions`, `MarkdownSaveOptions`, `MHTMLSaveOptions`, `XpsSaveOptions`, `DocSaveOptions`
- **Image handling**: `Rendering.Image`, `ImageFormat.*`, `ImageDevice`
- **PDF specifics**: `Rendering.Pdf`, `PdfEncryptionAlgorithm`, `PdfPermissions`
- **Markdown control**: `MarkdownFeatures.*`, `MarkdownSaveOptions`
- **Resource handling**: `MHTMLSaveOptions.ResourceHandlingOptions`, `ResourceHandlingOptions.MaxHandlingDepth`

### Rules
1. **Always dispose** `HTMLDocument` and any streams (`using` blocks) to free native resources.  
2. **Set a base URI** when the HTML contains relative resources (images, CSS, JS).  
3. **Match `SaveFormat` with the correct `ImageFormat`** (e.g., `SaveFormat.Png` → `ImageFormat.Png`).  
4. **Configure DPI and page size** before conversion for print‑quality outputs.  
5. **Enable/disable specific Markdown features** via `MarkdownSaveOptions.Features` to avoid unwanted element conversion.  
6. **When encrypting PDFs**, set both `UserPassword` and `Permissions` to enforce security.  
7. **For large batches**, prefer `Parallel.ForEach` or `Task.WhenAll` but limit concurrency to avoid memory pressure.  
8. **Validate output** (file existence, size > 0) immediately after conversion to catch silent failures.  
9. **Use custom `ICreateStreamProvider`** for cloud or encrypted storage scenarios.  
10. **Log every conversion** with source path, target path, and option summary for traceability.

## Warnings

- **Template/Data Binding Mismatch** – If placeholders in the HTML are not supplied, the output may contain raw tokens.  
- **Missing External Resources** – Forgetting to set `BaseUrl` or `ResourceHandlingOptions` can lead to broken images or CSS.  
- **File‑Path Issues** – Relative paths are resolved against the current working directory; use absolute paths or set `BaseUrl`.  
- **Memory Consumption** – Converting many high‑resolution images or large PDFs in parallel can exhaust RAM; monitor and throttle.  
- **Unsupported Elements** – Certain HTML5 features (e.g., `<video>`, `<canvas>`) are not rendered; they will be omitted or cause warnings.  
- **Encryption Limits** – PDF encryption algorithms have key‑size restrictions; using an unsupported algorithm throws an exception.

## Guidelines for Adding New Examples

1. **Self‑contained** – Include all `using` statements, create and dispose objects within `Main`.  
2. **Console Logging** – Use `Console.WriteLine` to output source, target, and key option values.  
3. **Follow the common pattern** (load → bind (optional) → configure → convert → log).  
4. **Naming** – File name should be snake_case, title in PascalCase, and reflect the primary operation.  
5. **Update statistics** – Increment `total_examples` and add the new file entry to the table with up to five key APIs.
